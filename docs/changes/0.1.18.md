# 栏况 0.1.18 契约：按 Esc 收起面板（和栏量 0.3.15 一致）

需求：老板 2026-11-27 01:37 NY。基线 master 62c349d（v0.1.17）。分支 `wip-0.1.18`。不出样稿（只改键盘行为，没有界面变化）。参照：栏量 v0.3.15（allen-bot-ctl/lan-liang，tag 在 bba8e86，`FloatingPanel` 的 `cancelOperation` / `sendEvent`）。

## 现状
栏况只有一个面板 `HoverPanel`（`App/Panel.swift`），是 nonactivating 的 NSPanel，`canBecomeKey` 返回 false，所以现在收不到任何按键。设置是面板里的一张卡（`model.showSettings`），不是单独窗口。面板有两种打开方式：鼠标悬停（预览），和点击菜单栏项（`debouncer.handle(.click)`，留住面板）；右键「设置中心」也会以点击态打开并直接进设置卡。

## 规则（和栏量 0.3.15 一样，由里往外一层一层退）
1. 设置卡上按 Esc：回到总览（相当于点「‹ 返回」），面板不收起。
2. 总览或其他卡片上按 Esc：收起面板，和点击菜单栏项再收起一样（`debouncer.forceHide()` + `hidePanel()`）。
3. 只认不带修饰键的 Esc（keyCode 53）。⌘ / ⌥ / ⌃ / ⇧ 加 Esc 不处理。
4. 收起后下次打开从总览开始（现有 `resetPage()` 行为不变）。

## 什么时候能收到 Esc
- `canBecomeKey` 改为 true。点击菜单栏项留住面板时，以及右键「设置中心」打开时，面板调用 `makeKey()`，这样不用再点一下面板，Esc 就直接生效。
- 鼠标悬停预览时不调用 `makeKey()`，不抢键盘焦点，Esc 交给前台应用；用户点一下面板后面板成为键盘焦点，Esc 生效。
- 只调 `makeKey()`，不调 `NSApp.activate`，前台应用不被切走。
- 不加全局或本地键盘监听，不申请辅助功能或输入监控权限。只在面板自己收到 Esc 时处理：`HoverPanel` 里接 `cancelOperation`，必要时同栏量一样在 `sendEvent` 里兜底。
- 面板能成为键盘焦点后，悬停收起、点外面收起、翻页、滚动等现有行为都不变。

## 验收
1. 单测：把 Esc 的分层判断抽成纯函数，覆盖三种情况：设置卡回总览、总览收起、带修饰键不处理。
2. CI：加 `--debug-esc-lifecycle`，依次跑「悬停预览不抢焦点、点击留住（成为键盘焦点）、进设置、⌘Esc 不处理、Esc 回总览、Esc 收起、再打开停在总览」，以 CI 输出 `DEBUG_ESC_LIFECYCLE ok` 为准，不加截图。
3. 老板 Mac 实机走查：
   - 点菜单栏项打开面板，直接按 Esc，面板收起；
   - 点开面板进设置，按 Esc 回总览，再按 Esc 收起；
   - 悬停展开后点一下面板，再按 Esc，面板收起；
   - 悬停预览时不点面板按 Esc，前台应用照常收到；
   - 收起后再打开，停在总览。
