# 栏况云端发布请求

- 已连接的 GitHub 账户只能把请求数据写到 `release-requests`。分支自己的信号工作流无写权限；接收方从 `master` 运行可信脚本，不执行该请求分支上的代码，也不读取它的工作流产物。
- 请求由当前仓库所有者账号发起，必须只修改一个既有请求文件，候选是当前 `master` 的完整提交 SHA，且其既有 CI 已成功。已有标签、已有 release、或较新的稳定标签仍待发布时拒绝。
- `dry-run` 只能读取，即使测试请求中的版本是未发布的稳定版本，也不会创建标签、触发 Release、调用签名或更新生产 feed。`publish` 要求已明确批准该版本，才运行有写权限的任务，并交由既有 Release 流程完成。
- 成功接受请求不等于已发版：以 Release 运行、公开资产、生产 feed 与实际客户端升级为各自独立证据。保持现有手动标签/发布路径和 Sparkle 密钥配置。
