# 栏况云端发布请求

- 此流程的发起步骤是把请求数据写到 `release-requests`。分支自己的信号工作流无写权限；接收方从 `master` 运行可信脚本，不执行该请求分支上的代码，也不读取它的工作流产物。
- 请求由当前仓库所有者账号发起，必须只修改一个既有请求文件，候选是当前 `master` 的完整提交 SHA，且其既有 CI 已成功。已有标签、已有 release、或较新的稳定标签仍待发布时拒绝。
- `dry-run` 只能读取，即使测试请求中的版本是未发布的稳定版本，也不会创建标签、触发 Release、调用签名或更新生产 feed。生产任务默认关闭，仅当仓库 Actions 变量 `LANKUANG_RELEASE_PUBLISH` 等于 `enabled`，且该版本已明确获准使用 `publish` 请求，才运行有写权限的任务，并交由既有 Release 流程完成。
- 成功接受请求不等于已发版：以 Release 运行、公开资产、生产 feed 与实际客户端升级为各自独立证据。保持现有手动标签/发布入口和 Sparkle 密钥配置。新的自动调用从默认分支触发，校验实际工作流提交与候选 SHA 一致，签名前与发布前重新核对标签，并在发布前比较最新稳定版本。同标签的入口共用一个并发组；不要在自动发布途中另用手动入口发不同标签，这个流程不改变仓库所有者已有的直接发版权限。连接器既有仓库权限不因本入口而收窄；不要把创建请求当作发布授权。
